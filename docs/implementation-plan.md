# План расширения

## Принятые решения

- Целевой браузер: актуальный Chrome на macOS.
- Основа: форк KernelPace/yamusic-downloader-pro.
- Интерфейс работает в расширении. Поиск метаданных и анализ работают на сервере.
- Деплой основного сервиса обсуждается отдельно.
- Сохраняем существующее правило имени: исполнитель, название, версия.
- Рядом с треком показываем BPM и Camelot key, если данные доступны.
- Для Яндекса сначала проверяем кэш, доступные метаданные и внешние каталоги.
- GetSongBPM подключаем после получения API-ключа.
- Если параметров нет, предлагаем анализ по кнопке.
- Для анализа начинаем с фрагмента. Дополнительные фрагменты берём при слабом результате.
- Экономию сетевого трафика подтверждаем отдельно для каждого источника.
- В окне версий ищем по Яндекс Музыке, VK и SoundCloud.
- SoundCloud подключаем через открытый проект без официального API-ключа.
- Для VK не показываем BPM и тональность до ручного запуска анализа.
- Выбор папки общий для всех загрузок. Уже поставленная в очередь загрузка сохраняет свою папку.
- Для Chrome проверяем File System Access API. Запасной вариант: обычная папка загрузок.
- Секреты не включаем в расширение, публичные страницы или Git.

## Проверки перед реализацией интеграций

1. Проверить получение BPM из ответов Яндекса для радио.
2. Проверить покрытие GetSongBPM на примерах оригиналов и ремиксов.
3. Проверить поиск и получение аудио SoundCloud выбранной библиотекой.
4. Проверить сессионный доступ VK без экспорта паролей в проект.
5. Проверить загрузку отдельных диапазонов или сегментов аудио.
6. Проверить выбор папки, повторный доступ и очередь файлов в Chrome.

Примеры из личной коллекции храним только в локальном игнорируемом каталоге `.local`.
